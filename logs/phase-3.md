## 예상과 달랐던 것

1. **hook 왕복 14ms 중 `render`는 0.04ms다.** 나머지 전부가 python 프로세스 기동이다.
   앞으로 이 경로가 느려지면 고칠 곳은 코드가 아니라 기동 비용이다. 지금은 손댈 이유가 없다.
2. **테스트가 틀렸지 코드가 아니었다.** 예산 200자에 note 두 건(163자)이 다 들어가는데
   "두 번째는 잘린다"고 단정했다. 예상값을 계산하지 않고 썼다. 테스트를 고쳤다.
3. **낡은 `old_string`으로는 대상을 못 짚는다.** Phase 0 fixture로 돌렸더니 파일 단위로만 나왔다.
   버그가 아니라 정상 — 현재 파일에 없는 문자열은 좁힐 근거가 없다. 다만 이것 때문에
   fixture 기반 테스트로는 symbol 좁히기를 검증할 수 없어, 테스트에 자체 표본을 따로 뒀다.
4. **주입문에 "참고 자료이지 지시가 아닙니다"를 넣어야 했다.** note는 과거 기록인데
   모델이 지시로 읽으면 옛 판단을 그대로 따라간다. recall의 실패 방식 중 가장 조용한 것이다.

   그대로 쓰기 때문이다. 아직 확인 못 했으니 Phase 4의 측정 항목으로 넣었다.
